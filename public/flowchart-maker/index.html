What is a flowchart?

A flowchart is a visual map of a process. It uses shapes to represent steps or decisions and connectors to show the order in which work moves. A good flowchart makes it easier to see where a process starts, what happens next, where a decision changes the route, and how the process finishes.

Flowcharts are useful before a process is automated, when a team is documenting how work currently happens, or when people need a shared explanation of a procedure. They can describe a simple checklist or a multi-step workflow with several decision paths.

How to make a flowchart

  1. Define the question or process. Give the diagram one clear purpose, such as explaining how a support request is handled. Write down where the process begins and what counts as a completed outcome.
  2. List the steps in plain language. Capture the actions in order before arranging shapes. Keep each action focused on one task and use short, verb-led labels such as “Review request” or “Send confirmation”.
  3. Identify decision points. Look for questions that can send the process in different directions. Phrase each one so its possible answers are clear, for example “Is the request complete?”
  4. Arrange the flow. Open the Sketchizi editor, place the steps on the canvas, and organise them in a consistent reading direction. Leave enough space for branches and labels.
  5. Connect the sequence. Add connectors to show what happens next. Label decision branches (such as “Yes” and “No”) close to the corresponding paths so the route is unambiguous.
  6. Review it with someone who follows the process. Trace every route from start to finish. Check that each branch leads somewhere meaningful and that the diagram matches the real process.

Common flowchart symbols

Consistent notation helps readers understand a diagram without having to decode every shape. These are widely used conventions:

  • Terminator (oval or rounded shape): marks the start or end of a process.
  • Process (rectangle): represents an action or task, such as checking an order or updating a record.
  • Decision (diamond): represents a question or condition that branches the flow, usually into two or more labelled outcomes.
  • Arrow or flowline: indicates the direction from one step to the next.
  • Input or output (parallelogram): is commonly used for information entering or leaving a process.

Choose a small, consistent set of symbols. If a diagram uses a special convention, include a short legend rather than expecting readers to guess.

Example: support ticket triage

Imagine a team receiving a support request. A simple flow might look like this:

Start: New ticket arrives

Process: Check the request details

Decision: Is enough information provided?

No: Ask the customer for more information, then review the ticket again

Yes: Categorise and assign the ticket

Process: Investigate and respond

End: Close the ticket when the issue is resolved

This small example already reveals a loop: an incomplete request returns for review. Drawing that loop makes the rework visible and gives the team something concrete to improve.

Where flowcharts are useful

Business operations

Document approvals, onboarding, purchasing, order fulfilment, and hand-offs between roles.

Software and IT

Explain application logic, incident response, deployment steps, and troubleshooting paths.

Education and training

Break a procedure into teachable steps and show learners how different choices affect the outcome.

Make flowcharts easier to read

  • Give the diagram one main purpose; split unrelated processes into separate diagrams.
  • Use short labels that describe actions or ask direct questions.
  • Keep the main path visually consistent, and make branches easy to distinguish.
  • Label decision outcomes directly on their connectors.
  • Avoid crossing lines where possible; reposition steps or use a clear connector route.
  • Include exceptions and loops that change what someone actually does, but leave irrelevant detail out.
  • Ask a new reader to follow the diagram without verbal explanation. If they get stuck, revise the layout or labels.

Flowchart maker FAQs

What should I include in a flowchart?

Start with a clear beginning and end, the actions that move the process forward, and any decisions that create different paths. Add only the details readers need to understand or carry out the process.

What is the difference between a flowchart and a workflow?

A workflow describes how work moves between steps, people, or systems. A flowchart is one way to represent that workflow visually, including its sequence and decision branches.

How do I show a yes-or-no decision?

Use a decision shape for the question and draw a separate connector for each outcome. Label the connectors “Yes” and “No” (or the actual outcomes) so readers can follow each route.

Can I update a flowchart when a process changes?

Yes. A diagram on the Sketchizi canvas can be revisited and edited as the process evolves. Review all affected branches after changing a step.
