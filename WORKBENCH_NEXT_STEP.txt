Current milestone: Workbench query / index hypothesis 0.24.

Added a synthetic, evidence-gated PostgreSQL index hypothesis distinct from concurrency, mean service-time, and write-contention trials. It requires a typed Reads from path, recorded database reads in the selected load scenario, a contained table, and an explicitly chosen eligible column when multiple candidates exist. The model changes only the assumed share of reads that benefit from an index; the speedup factor is fixed and disclosed. The engine does not parse SQL or run PostgreSQL query planning.

An index is only added to the semantic schema after the user explicitly selects Add candidate index to schema model. SQL artifact generation then emits validated CREATE INDEX DDL from the schema. Changing the schema invalidates prior experiment results and requires artifact regeneration.

Run locally from sketchizi-main:
1. npm ci
2. npm run build
3. npm run test:database-index-improvement
4. npm run test:simulation
5. npm run test:workbench-artifacts
6. npm run dev

Manual browser gate: create/open the React -> REST -> PostgreSQL POC, confirm assumptions, run 5x traffic, explicitly select a candidate table column in Query / index hypothesis, run the trial, and verify before/after metrics plus trace evidence. Then explicitly accept the candidate index into the table schema, regenerate SQL, and confirm the CREATE INDEX statement appears. Save/reopen and confirm schema/model freshness behavior.

Current verification boundary: Node regression tests and JSX syntax parsing passed in this environment.
